# DaVinci Markdown Editor 0.4.1

Hotfix for a regression introduced in 0.4.0: **flowcharts with `subgraph` clusters drew their arrows
away from the shapes**. Clustered diagrams are now rendered exactly as Mermaid produced them; flat
flowcharts and state diagrams keep the orthogonal routing from 0.4.0.

## The bug

Mermaid writes a clustered layout with the paths of every subgraph in that cluster's own coordinate
system (the group carries a `transform`), while the router measured node boxes in the root SVG
coordinates. The new route was written back into the local `d`, so the browser applied the cluster
transform a second time. On the customer document the four “configuration” clusters (3.3) kept their
shapes but the arrows drifted out to the right, and a pair of empty boxes with vertical arrows
appeared beside them; section 3.2 lost the visible relation inside its second frame.

## The fix

- `src/mermaid/route/svg.ts` gains an explicit guard: a flowchart that Mermaid drew with clusters
  (`g.cluster`, `g.clusters > g`, `g.subgraph`, `g.subgraphs > g`) is returned untouched, before any
  measurement or mutation. The check lives in `isClusteredFlowchart()` and is covered by tests.
- The router keeps working for flat flowcharts and for `stateDiagram-v2`: those keep their ports,
  separate lanes for counter-edges, rectangular loops and the reference typography.
- Cache versions move to `render-5` / `layout-3`, so a clustered diagram cached by 0.4.0 is not
  served again.

Re-routing clustered graphs properly (root-coordinate measurement, inverse-transforming every point
before writing `d`, cluster frames as nested obstacles) is deliberately left for a later release:
the hotfix restores correctness first.

## Verification

- `npm run verify`: typecheck, ESLint, Prettier, **366 frontend tests** (5 new for the cluster
  guard), `cargo fmt`, `cargo clippy -D warnings`, 85 Rust tests — all exit 0.
- Browser check against the real Render Lab and the source document:
  - clustered flowchart (3.3) → the post-processor returns the SVG **byte-for-byte unchanged**;
  - flat flowchart from the render spec → still changed by the router;
  - 3.3 renders four labelled frames with three shapes and two arrows each, all arrows inside their
    own frame; 3.2 renders two frames, the double-headed relation keeps both arrow heads, and the
    `PEREPISKA ~~~ TZ` separator stays invisible.
- The two reference diagrams from `DaVinci_Mermaid_Render_TZ.md` (Goodland flowchart, reservation
  state diagram) still pass the independent geometry check: 0 crossings, 0 shared segments, 0 routes
  through a shape, 0 label collisions.
- Standalone SVG export still opens on its own; reopening the document and switching themes does not
  bring the old geometry back from the cache.

## Upgrade notes

Settings, sessions and files carry over from 0.4.0. No document changes are needed; clustered
diagrams simply go back to Mermaid's own (correct) routing.
