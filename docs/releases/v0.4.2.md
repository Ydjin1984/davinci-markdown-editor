# DaVinci Markdown Editor 0.4.2

Linux hotfix. 0.4.1 installed cleanly on Ubuntu, but the window stayed empty — and on some machines
the package could not start at all. Both causes are fixed, and the Linux build is now pinned to the
oldest distribution the project supports.

## The blank window

Since 2.42 WebKitGTK hands frames to the compositor through DMA-BUF, and the buffers come from GBM.
On the NVIDIA proprietary driver — and in some virtualised, remote-desktop and multi-GPU
configurations — GBM refuses to allocate them:

```text
KMS: DRM_IOCTL_MODE_CREATE_DUMB failed: Permission denied
Failed to create GBM buffer of size 1360x880: Permission denied
```

The process stays alive and the window is created, but nothing is ever painted into it. To the user
this looks exactly like an application that installed but does not work: a white rectangle with no
menu, no editor and no error. This is [WebKit bug
261874](https://bugs.webkit.org/show_bug.cgi?id=261874), and it still reproduces on WebKitGTK 2.50
with current NVIDIA drivers.

0.4.2 sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` before the webview is created. WebKit then uses its
shared-memory transport, which is slower per frame but always paints; for a text and vector-diagram
editor the difference is not observable. The variable is only set when the user has not chosen a
value, and `WEBKIT_DISABLE_DMABUF_RENDERER=0` is the documented way to keep the accelerated path on
a driver that copes with it.

## The glibc mismatch

0.4.1 was built on `ubuntu-latest`, which is Ubuntu 24.04 (glibc 2.39). Every launch on Ubuntu 22.04
printed:

```text
weak version `GLIBC_2.39' not found (required by davinci-markdown)
```

and on a distribution with an older loader the same requirement is fatal. The AppImage carried the
24.04 runtime as well, so it had the same floor.

The Linux job now builds inside a pinned `ubuntu:22.04` container, so the binary and the AppImage
target glibc 2.35 — Ubuntu 22.04 and newer, Debian 12 and newer. CI reads the required symbol
versions out of the built `.deb` and fails the build if anything above 2.35 appears, which keeps the
baseline from drifting when GitHub retires the old runner images.

## Desktop integration

- The desktop entry now claims all five format families. `MimeType` comes from
  `bundle.fileAssociations` through `{{mime_type}}`, so Markdown, JSON, CSV, LOG and XML all appear
  in _Open With_ and can be set as the default — previously only `text/markdown` was claimed.
- LOG files register as `text/x-log` instead of `text/plain`, matching the shared-mime-info
  registration the package ships. Claiming `text/plain` made the entry compete for every `.txt`
  file.
- `Exec` keeps `%F`, so the file manager still hands selected documents to the running instance.
- The CI check now requires each of the five MIME types, not just `text/markdown`.

## Verification

- Reproduced on Ubuntu 22.04.5 with the NVIDIA 580.178.04 driver and WebKitGTK 2.50.4: the 0.4.1
  binary shows a blank white window; with the DMA-BUF renderer disabled the shell, editor, preview,
  tabs and settings all render normally.
- `npm run verify`: typecheck, ESLint, Prettier, 366 frontend tests, `cargo fmt`,
  `cargo clippy -D warnings`, 85 Rust tests.
- The `.deb` built by CI is unpacked in CI and checked for the five MIME types, the MIME
  registration file, the executable and a glibc requirement no newer than 2.35.
- Clean install on Ubuntu 22.04: `apt install ./…deb`, launch from the application menu — the
  window paints, `davinci-markdown --version` prints without a loader warning, and double-clicking a
  `.md` file opens it in a tab.

## Upgrade notes

Settings, sessions, recent files and the open workspace carry over from 0.4.1. Nothing in the
document formats changed. If a machine was previously worked around by exporting
`WEBKIT_DISABLE_DMABUF_RENDERER=1` by hand, that export can be removed.
